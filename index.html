JIG 생애관리 시스템 통합 및 고도화

분산된 JIG 관리를 하나의 시스템으로 통합하고, 사용자의 실수를 시스템 검증으로 차단했습니다.
JIG란? 제품을 가공하고 조립하고 검사할 때 쓰는 보조 도구입니다. 도구 자체가 마모되거나 손상되면 제품 품질에 바로 영향을 줍니다.
소형과 중대형 사업부가 서로 다른 시스템(EMS/MES)으로 JIG를 관리하던 상황에서, 2023년 중대형 JIG로 인한 불량이 전체 이상의 23% 이상을 차지했습니다.
PROBLEM
🧩 분산된 관리 체계
시스템 2개, 기준 상이
소형 EMS · 중대형 MES
사업부마다 관리 화면과 기준이 달라 이력 추적이 어렵고, 관리가 사용자 판단에 의존했습니다.
⚠️ 품질 리스크
JIG 기인 불량 23% 이상
그중 주기 초과 사용 54% 이상
교체 주기를 넘겨 사용된 JIG가 불량의 절반 이상을 차지했지만, 이를 막는 시스템적 장치가 없었습니다.
ACTION
1🧱 표준화와 통합
소형과 중대형 조직과 협업해 JIG 생애주기(생성 → 입고 → 장착 → 사용 → 수리 → 폐기) 프로세스를 표준화하고, EMS 기준 단일 시스템으로 통합했습니다. 'JIG그룹'이라는 상위 관리 체계와 창고관리 기능을 도입해 개별 JIG의 위치까지 추적할 수 있도록 만들었습니다.
BEFORE사업부마다 기준과 화면이 다르고 위치 추적이 불가능했습니다.
AFTEREMS 단일 기준으로 통합해 개별 위치까지 추적할 수 있게 되었습니다.
2🛡️ Human Error Zero
JIG 그룹별 운영 방식을 정의하고, 필수 프로세스를 시스템 검증(Validation)으로 강제했습니다. 일괄 등록 시 입력 자동 검증과 그룹별 고정 ID 채번 체계도 함께 구축했습니다.
🚫 조립되지 않은 상태의 장착 차단
✅ 정상 조립 상태만 장착 허용
3📊 데이터 기반 KPI
JIG그룹과 설비, 개별 단위로 교체 주기(SPEC) 대비 사용량과 해당 시점의 불량 데이터를 함께 볼 수 있는 리포트 화면을 설계해, 숙련자 경험에 의존하던 판단을 데이터 기반으로 전환했습니다.
RESULT
주기 초과 사용 비중
100% 제거 · 확정
🏅 외부 인정
JIG 운영 KPI 리포트가 고객사 IATF(자동차 품질경영 표준) 점검 지표로 채택되었습니다. · 확정
기준정보 변경 요청도 월 30건에서 3건(약 90% 감소, 확정)으로 줄었습니다. 분산되어 있던 관리 기준을 하나로 모으고, 판단을 사람이 아니라 시스템 검증에 맡기면서 품질 리스크를 구조적으로 낮췄습니다.

설비 정기점검 일정 자동화

수작업 일정 계산을 시스템 로직으로 대체하고, 반복되는 조정 업무를 자동화했습니다.
라인이 장기간 멈추거나 PM(예방점검) 일정을 조정해야 할 때마다, 담당자가 매번 엑셀로 다음 작업일을 손으로 계산해야 했습니다.
PROBLEM
⏸️ 예외 상태 부재
작업표준 상태가 ACTIVE와 INACTIVE뿐이라, 장기 비가동 후 재개할 때마다 다음 점검일을 수동으로 다시 계산해야 했습니다.
📅 계획 영향도 파악 불가
PM 계획서가 캘린더로 건수만 보여주어, 일정을 고르게 배분하려면 담당자가 엑셀로 직접 계산해야 했습니다.
ACTION
1⏸️ HOLD 상태 신설
작업표준에 HOLD(일시중지) 상태를 새로 정의했습니다. HOLD에서 ACTIVE로 전환할 때 HOLD 기간을 반영해 다음 작업일을 자동으로 재계산하는 로직을 설계하고, 결재와 변경 이력 관리에 연동했습니다.
BEFORE설비 1대(작업표준 50~200개) 재개 시 약 3시간의 수작업이 필요했습니다.
AFTER일괄 전환과 자동 계산으로 약 10분에 완료됩니다. (대표 케이스)
2📋 PM 계획서 개선
일정을 변경할 때 이후 일정에 미치는 영향을 실시간으로 확인하고, 여러 작업을 한 번에 수정할 수 있도록 화면을 개선했습니다.
BEFORE4단계를 N회 반복해야 하고 30분 이상 소요되었습니다.
AFTER3단계 단일 흐름으로 5분 이내에 완료됩니다. (대표 케이스)
RESULT
HOLD 전환 처리시간
약 94% 감소 · 대표 케이스
🧮 일정 조정 단계 축소
반복 4단계에서 단일 3단계 흐름으로 단순화했습니다. (대표 케이스)
운영 예외 상황을 시스템 로직으로 흡수하면, 반복되는 수작업을 구조적으로 제거할 수 있다는 것을 확인했습니다.
INSIGHT
예외를 상태로 설계하면 반복이 사라집니다
비정상 상황을 임시방편이 아니라 정식 상태로 정의하면 자동화가 가능해집니다.
자동화의 시작은 상태 정의입니다
계산 로직보다 먼저 상태를 명확히 정의하는 것이 자동화 설계의 출발점임을 배웠습니다.

설비 고장 다운타임 중복 집계 정상화

잘못 쌓이던 운영 데이터를 실제 업무 흐름에 맞게 바로잡아 의사결정 신뢰도를 높였습니다.
설비 고장(BM) 조치 중 추가 고장이 발생하면, 현장에서는 하나의 조치 흐름이지만 시스템은 다운타임을 두 번 집계하고 있었습니다.
PROBLEM
🔁 다운타임 이중 집계
조치 중 발생한 추가 고장이 별도 이벤트로 처리되어, 실제보다 다운타임이 부풀려졌습니다.
📉 KPI 신뢰도 저하
다운타임을 기반으로 계산되는 MTTR과 MTBF 등 설비 KPI가 왜곡되어 의사결정 근거로 쓰기 어려웠습니다.
ACTION
1🔧 이벤트 경계 재정의
보전 엔지니어의 조치 프로세스를 단계별로 분석해 작업지시(WO)의 진행 상태와 조치 시작·종료 기준을 재정의했습니다. 진행 중인 BM 도중 발생한 추가 고장은 먼저 시작된 BM의 시작 시점을 기준으로 산정하도록 로직을 설계했습니다.
BEFORE고장 이벤트마다 개별 집계되어 대표 샘플에서 27분으로 기록되었습니다.
AFTERWO 상태 기준으로 재정의해 대표 샘플에서 13분으로 보정되었습니다.
RESULT
샘플 케이스 다운타임
대표 케이스 기준 보정
📐 데이터 신뢰성
설비 KPI(MTBE/F) 데이터 정확도를 개선하고, 데이터 기반 의사결정 신뢰도를 강화했습니다. (정성 성과)
운영 데이터가 잘못 쌓이면 잘못된 의사결정으로 이어지기 때문에, 집계 기준을 현장 업무 흐름과 일치시키는 것이 데이터 신뢰성의 출발점이라는 것을 확인했습니다.
INSIGHT
숫자보다 기준이 먼저입니다
집계 기준이 잘못되면 아무리 정교한 지표도 의미가 없다는 것을 배웠습니다.
현장 흐름을 모르면 정확한 집계도 설계할 수 없습니다
보전 엔지니어의 실제 조치 흐름을 이해해야 올바른 집계 기준을 세울 수 있었습니다.

2025년 출고 데이터 기준으로 전 법인에 적용할 경우 약 2.1억 원의 구매 비용 절감 가능성을 모델링으로 검증했습니다. 실제 절감액이 아닌 시뮬레이션 추정치입니다.
